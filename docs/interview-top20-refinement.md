# Top twenty: stronger progression before push

Refined October 8, 2026. All twenty featured questions now have four logical parts: three baseline parts with explicit observations, followed by an optional changed-requirement discussion. They remain one platform ticket with the existing public APIs. The refinement adds harder examples within the stated contracts and does not expand those contracts silently. The logger brief explicitly clarifies that suppressed events invoke neither the clock nor sinks, matching the reviewed implementation and its new observation check.

## What changed

- Replace generic checkpoint text with a question-specific model/diagnosis part, implementation part, and pressure-test part. Each includes a concrete acceptance observation.
- Add one visible pressure fixture and one separate independent fixture per question. Public and grading fixtures use different input values/forms, with expected grading results retained on the server.
- Show the parts in the interview brief, including an explicit optional-discussion label. Candidate responses contain only number, title, task, acceptance and mode; they do not expose private case ids, weights or expected results.
- Map every independent case for a featured question to exactly one of the three baseline parts. The publication gate rejects missing/uncovered/duplicate part coverage and any graded discussion part.
- Add reviewer anchors for a plausible wrong assumption and a changed requirement. Explanations remain a human judgment; passing behavioral cases alone does not certify comprehension.

## Scope and fairness

The five additional practice exercises retain their existing briefs and suites. Featured order and original editorial selection scores are unchanged. There is no automatic stage unlocking, per-part time limit or new per-part scoring formula. The parts organize the existing whole-ticket contract; independent behavioral scoring still uses the declared case weights. The added cases improve coverage, not a claim of exhaustive correctness.

Part 3 asks the candidate to verify an outcome independently and explain a second counterexample. Its behavioral property is tested; the explanation and AI-output review still require a reviewer. Part 4 has no coding requirement or independent cases and does not change the automated score. If a future run turns a discussion into a coding variant, it needs its own explicit contract, fixtures and calibration first.

Catalogue latency/counter integrity, rendered React behavior and pricing delegation retain their existing explicit review requirements. New time boxes and difficulty labels still require mock-interview calibration. No user scores are silently recalculated.
